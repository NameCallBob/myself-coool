## C 級 —— 測試/驗收階段抓到,上線前就修掉(建議保留並補上時間點)

你說得對:這些是測試時發生的,不是上線後發生的。那它們就不是「系統曾經外洩」,
而是「我的驗收流程會抓到這種東西」——**這是加分項**。
唯一的問題是站上把漏洞和時間點寫在不同段落,讀者容易誤會。
**建議:全部保留,但在每條漏洞敘述裡直接寫明「驗收階段發現」「上線前修復」。**

- [ ] **L1575** `agm-evoting-system` — 身分證後四碼與電話後三碼原本以明碼存庫,作為登入比對依據——資料庫一旦外洩就是直接可識別的個資;而且表裡已有既存明碼資料,不能砍掉重灌。
- [ ] **L1672** `ecobao` — 三個 repo 都要公開,後端原本把 SECRET_KEY、資料庫帳密與郵件設定寫死在程式碼裡,直接開源等於外洩設定。
