## 1. 為什麼「投影布」這個隱喻站得住腳

它不是隨便挑的裝飾。你**真的站在投影布前面報告過**——
2023 年代表商業發展研究院在 DIGI⁺Talent 發表、2024 年在科工館的 AI 健康應用計畫。
所以「整個網站是一場簡報」這件事在你身上是**有來歷的**,不是套皮。
這一點很重要:參考站裡最難忘的幾個(Bruno Simon 開車逛作品集、Cassie Evans 的手繪書桌、
Lynn Fisher 每年重做一次)之所以成立,都是因為那個點子跟本人有關,而不只是特效好看。

## 2. 技術選型(GitHub 實查,2026-09-12)

### 2.1 動畫引擎 — 二選一或併用

| 專案 | ⭐ | 定位 | 對這個站的適用性 |
|---|---|---|---|
| `juliangarnier/anime` | 72.8k | 輕量動畫引擎 | 語法簡潔,但複雜的捲動編排要自己接 |
| `motiondivision/motion` | 33.6k | React 優先,混合原生瀏覽器動畫 | **元件層動畫最順**:layout animation、進場退場、手勢。體積小 |
| `greensock/GSAP` | 28.4k | 時間軸編排 + ScrollTrigger | **複雜編排最強**:多段時間軸、捲動釘選、元素飛行。你說的「很複雜」指的就是這種 |
| `pmndrs/react-spring` | 29.1k | 彈簧物理 | 手感好,但編排能力不如 GSAP |

**建議:GSAP(主)+ Motion(輔)。** GSAP 負責投影片切換與捲動編排這種需要精準時間軸的部分,
Motion 負責元件層的小動畫與 layout 過場。兩者併用在業界很常見,不算堆套件。

### 2.2 簡報骨架 — **借鑑,不整包採用**

| 專案 | ⭐ | 可借鑑的東西 |
|---|---|---|
| `hakimel/reveal.js` | 72.3k | fragment(逐步揭露)的狀態模型、鍵盤導覽、每張投影片一個 URL、speaker notes |
| `slidevjs/slidev` | 48.6k | 開發者導向的版面配置與程式碼區塊呈現 |
| `impress/impress.js` | 38.2k | **最關鍵的參考**:用 CSS 3D transform 把「一整片大畫布」當成空間,鏡頭在上面飛。這正是「一張投影布放上很多資訊」的做法 |
| `FormidableLabs/spectacle` | 10.2k | React/JSX 寫投影片的 API 設計 |

⚠️ **不建議整包裝上任何一個**。它們都是「接管整個頁面」的框架,
會跟你現有的 Next.js App Router、next-intl 雙語、SSG 靜態輸出、17 筆案例頁打架。
正確做法是讀它們的原始碼,把 fragment 狀態機 + 鍵盤導覽 + URL 同步這三件事
自己實作成約 200 行的元件——這本身就是可以拿出來講的前端能力。

### 2.3 投影布質感 — 不需要任何套件

全部是 CSS/SVG,而且 `globals.css` 裡已經有一半的材料(現成的 `feTurbulence` noise overlay):

- **布面織紋**:沿用現有的 SVG `feTurbulence`,調高一點 opacity
- **投影機光錐**:`conic-gradient` + `radial-gradient` + `blur()` + `mix-blend-mode: screen`
- **梯形變形(keystone)**:`transform: perspective(1200px) rotateX(2deg)`,模擬投影機沒對準
- **邊緣暗角**:radial vignette
- **色散 / 掃描線**:`repeating-linear-gradient` 極低 opacity,克制使用
- **開機亮起**:`brightness()` + `opacity` keyframes,配一次輕微的抖動

### 2.4 「可愛」——接上先前的插畫頭像決策

你先前選了「用插畫或頭像代替真實照片」,這裡剛好合流:

| 專案 | ⭐ | 說明 |
|---|---|---|
| `rive-app/rive-wasm` | 967 | **首選**。有狀態機,能做「會看滑鼠、會眨眼、點一下有反應」的互動角色,檔案小 |
| `airbnb/lottie-web` | 32.1k | After Effects 匯出,只能播放不能互動,體積較大 |

一隻小投影機當吉祥物:開場時「喀」一下亮起來、換投影片時抖一下、滑鼠靠近時鏡頭轉過來。
這一個元素同時解決「可愛」「頭像」「展現前端技術」三件事。

### 2.5 換頁動畫 — 用原生的,零體積

Next.js 16 支援 **View Transitions API**,跨頁過場不需要 `barba.js`(⭐13k,那是給非 SPA 用的)。
用原生 API 做出跨頁元素連續飛行,比裝套件更能展現你懂平台。

### 2.6 明確不建議(至少 v1 不要)

- `pmndrs/react-three-fiber`(⭐32.2k)+ `drei`:真正的 3D 體積光很美,
  但 three.js 壓縮後仍有數百 KB,而這個站是 GitHub Pages 靜態站、LCP 本來就已經是問題
  (自架字型 10MB / 223 個 woff2 還沒處理)。3D 留到 v2,先把 CSS 3D 的版本做出來。
- `darkroomengineering/lenis`(⭐15.8k):**剛移除,不要裝回來**。
  它劫持原生捲動、行動端手感更差,而且是最明顯的模板訊號。
  投影片切換要的是「分頁」不是「平滑捲動」,本來就不需要它。

## 3. 版面概念

**一張投影布,上面是一疊投影片,鏡頭在畫布上移動。**

- 進站:暗場 → 投影機亮起 → 光錐展開 → 第一張投影片浮現
- 導覽:`←` `→` 或滾輪換片,右下角頁碼與進度條,`F` 全螢幕,`Esc` 叫出總覽(所有投影片縮圖)
- 每張投影片是**高密度**的,不是一句話配大留白:
  1. 封面(姓名、身分、三個 live 連結)
  2. **經歷流程圖**(`docs/career-flow.md` 那張,SVG path 逐條畫出來)
  3. 專案矩陣(17 筆,依領域分色)
  4. 技術棧地圖(含**伺服器/維運**這條新的線)
  5. 數據磚牆(728 端點、1,112 測試、9,138 筆遷移…,數字滾動計數)
  6. 原則(現有的三條)
  7. 聯絡
- 每張投影片用 reveal.js 式的 **fragment 逐步揭露**,所以「放上很多資訊」不會一次砸到臉上
- 每張投影片有自己的 URL(`/deck/2`),可以直接連過去,SEO 與分享都不會壞

## 4. 一個必須講的取捨

這個站目前最強的資產是 17 筆經過查證、連失敗率與未還技術債都寫出來的案例,
它們的可信度有一部分來自**克制**。如果把案例頁也包進重動畫的簡報裡,
會從「太像 AI 生成」換到另一個問題:「看起來很炫但沒有內容」。

**建議雙軌**:首頁 / about / 新的 `/deck` 走投影布與重動畫;
**案例頁維持現在的文件風**。兩種質感的刻意對比,本身就是設計判斷的展示——
而且對招募端來說,「這個人知道什麼時候該收」比「這個人會做動畫」更值錢。
